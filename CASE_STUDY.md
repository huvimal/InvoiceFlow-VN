# InvoiceFlow-VN v0.2 — Reviewable invoice extraction

## Problem

The first prototype could review one image and compare three transformations of
one synthetic invoice. That established a smoke test, but did not show how the
system handles different layouts, missing fields, extra predicted items or a batch
of documents awaiting human review.

## Implementation

The upgrade adds 20 independently valued synthetic invoices across five layout
families. Twelve dev cases and eight layout-held-out test cases support separate
iteration and evaluation. The ground truth intentionally preserves absent fields
and a printed arithmetic error, rather than silently repairing source documents.

The new scorer performs minimum-mismatch one-to-one item assignment. Reordering
is allowed; extra duplicate items, missing rows, wrong numeric/date values, and
fabricated values for absent fields are recorded. Provider and schema failures are
tracked separately and count against end-to-end processed-invoice success.

The UI keeps each source image, latest saved draft, successful raw AI extractions,
and a content-bound human approval. A changed saved draft, new extraction, or failed
retry invalidates approval. Only approved documents enter the batch export. Separate
invoice and item CSVs avoid repeating invoice totals during aggregation. A JSON
sidecar records the source hashes and raw-to-reviewed changes.

The benchmark checkpoints each case, limits live requests, stops on HTTP 429, and
requires explicit retry/resume. Input/model/prompt/code fingerprints prevent mixing
incompatible runs. Prior failed attempts remain visible if retried.

## Validation

40 automated tests cover schema/arithmetic, line assignment against brute-force
optima, null hallucinations, extra/missing rows, API error categories, request budgets,
resume behavior, duplicate protection, raw preservation, approval invalidation and
Streamlit interaction flows. No real Groq requests are made by these tests.

Replay data deliberately contains errors to validate the scorer. Replay percentages
are **not model accuracy**. A new 20-invoice live benchmark has not been performed
as part of this upgrade. The earlier one-invoice live pilot is a separate result.

## Limits and next evidence

The collection is synthetic and generated by a shared renderer. References are from
source values, not independent human transcription. A stronger external claim needs
permitted real documents, independent reference checks and completed live reports.
The application remains a local session-based prototype: no PDF ingestion, signed
audit, authenticated reviewers, durable review database, or accounting-system integration.
